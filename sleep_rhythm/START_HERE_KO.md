# 리듬 v2.2 — 사용 방법과 배포 과정

리듬은 수면을 버튼 두 개로 기록하고, 내일 집중할 교시에 맞춰 오늘 밤 잠들 시각을 계산하는 교육·자기관리용 웹앱입니다. 휴대폰 화면에 맞춰 만들었습니다. 계산과 분석은 Python 서버가, 화면과 기록 보관은 브라우저가 맡습니다. 기록은 사용하는 브라우저에만 저장되고 서버에는 남지 않습니다.

## 1. 내 컴퓨터에서 실행하기

1. ZIP **압축을 풀고** `sleep_rhythm` 폴더를 엽니다. ZIP 안에서 바로 실행하면 `run.py`를 찾지 못합니다.
2. Python 3.11 이상을 설치합니다(3.11~3.15에서 테스트, 3.15는 베타판). Windows 설치 화면에서는 **Add python.exe to PATH**를 선택합니다.
3. 예전 버전을 실행해 둔 검은 창이 있으면 먼저 닫습니다.
4. 실행합니다.
   - Windows: `start_windows.bat`를 더블클릭합니다(검은 창은 켜 둡니다).
   - macOS: 폴더에서 터미널을 열고 `python3 run.py`를 실행합니다(`sh start_macos.command`도 같음).
   - 그 밖의 운영체제: `python3 run.py` 또는 `python run.py`.
5. 브라우저가 자동으로 열립니다. 열리지 않으면 **http://127.0.0.1:8000** 에 접속합니다. 시작 안내 창이 뜨고 설정 탭 맨 아래에 ‘리듬 v2.2’가 보이면 새 버전입니다. 예전 화면이 보이면 `Ctrl+Shift+R`로 새로고침합니다.
6. 끝낼 때는 실행 창에서 `Ctrl+C`를 누르거나 창을 닫습니다. 다시 실행하면 같은 브라우저의 기록이 그대로 있습니다.

- 컴퓨터에서 휴대폰 화면처럼 보려면 Chrome·Edge에서 `F12`를 누른 뒤 `Ctrl+Shift+M`을 누르고, 위쪽 목록에서 휴대폰 기종을 고릅니다.
- 실행 창에 **서버를 열 수 없습니다**가 나오면 이미 켜 둔 리듬 실행 창(예전 버전 포함)을 닫고 다시 실행합니다. 다른 프로그램이 8000번 포트를 쓰고 있으면 `python run.py --port 8001`처럼 다른 포트를 씁니다.
- 로컬 실행에는 추가 설치가 필요 없습니다. Windows에서 서울·UTC가 아닌 시간대를 고를 때만 `python -m pip install -r requirements.txt`를 실행합니다.
- `index.html`을 더블클릭해서 여는 방식은 동작하지 않습니다. 반드시 `run.py`를 실행한 주소로 접속합니다.
- 새벽에 계산하면 “8시간을 채우기 어려워요”가 나오는 것이 정상입니다. 오늘 아침 기상까지 남은 시간으로 계산하기 때문입니다. 기상 시각을 지금부터 2시간 안쪽(예: 새벽 4시 30분이면 06:00)으로 바꾸면 다음 날 아침을 기준으로 계산합니다.
- 친구들이 계속 쓰려면 4장처럼 인터넷에 배포한 주소가 필요합니다.

### 1.1 배포 전에 내 휴대폰으로 시험하기 (같은 Wi-Fi)

1. 컴퓨터와 휴대폰을 같은 Wi-Fi에 연결합니다.
2. `start_windows_phone.bat`를 더블클릭합니다(macOS·그 밖: `python3 run.py --host 0.0.0.0`).
3. Windows 보안 경고(방화벽) 창이 뜨면 **액세스 허용**을 누릅니다.
4. 실행 창의 **같은 Wi-Fi의 휴대폰에서 열 주소**(예: `http://192.168.0.12:8000`)를 휴대폰 브라우저 주소창에 `http://`까지 그대로 입력합니다.

- 시험용 방식입니다. `https`가 아니어서 홈 화면 설치와 오프라인 실행은 되지 않고(나머지 기능은 같음), 컴퓨터의 실행 창을 닫으면 쓸 수 없습니다.
- 여기서 만든 기록은 이 주소에만 저장되어, 배포한 앱에 쌓인 기록과 섞이지 않습니다.
- 휴대폰에서 열리지 않으면: 같은 Wi-Fi인지 확인합니다. 집 Wi-Fi가 Windows에서 ‘공용 네트워크’로 잡혀 있으면 방화벽 창에서 공용에도 체크해야 합니다. 창을 이미 닫았다면 **Windows 보안 → 방화벽 및 네트워크 보호 → 방화벽에서 앱 허용 → 설정 변경**을 누른 뒤 Python의 개인·공용을 체크합니다(시험 후 같은 곳에서 해제). 학교·공공 Wi-Fi는 기기끼리의 접속을 막는 경우가 많으니, 그때는 휴대폰 핫스팟에 컴퓨터를 연결해 시도합니다.

## 2. 사용 방법

### 2.1 시작 안내

앱을 열 때마다 사용법과 **어려운 말 풀이**(수면압 S, 일주기 기준 C, 각성 지표 AL, 모형 각성도 높음·낮음, 필요 수면, 권장 취침 구간, 준비 기간)가 나옵니다.

- **닫기**: 창만 닫습니다. 새로고침하거나 앱을 다시 열면 다시 보입니다.
- **이 창 재접속까지 보지 않기**: 앱을 완전히 닫았다가 다시 열 때까지 보이지 않습니다.
- 언제든 오른쪽 위 **?** 버튼이나 설정 탭의 **사용법·용어 풀이 다시 보기**로 다시 볼 수 있습니다.
- 수면 기록 중에 앱을 열면 안내 대신 수면 화면이 먼저 나옵니다.

### 2.2 홈 화면 (한 화면에 모두 보임)

위에서부터 다음 순서입니다.

| 칸 | 하는 일 |
|---|---|
| 오늘 밤 권장 취침 | **최근 기록으로 취침 시각 계산하기** 버튼. 계산하면 권장 구간(예: `22:30–23:00`)과 “늦어도 23:00 · 평소보다 30분 일찍”을 보여 주고, **계산 근거 ›** 로 자세한 내용을 봅니다. |
| 나의 기록 상태 | 연속 기록 일수, 최근 평균 수면, 지난 수면. “준비 중 3/5”처럼 계산까지 남은 일수와 빠진 날을 알려 줍니다. 기록이 없으면 **예시로 둘러보기** 버튼이 보입니다. |
| 내일 언제 집중할까요? | 1~7교시·방과후 중 집중해야 할 시간을 누릅니다(여러 개 가능, 다시 누르면 해제). 설정에서 8·9교시를 추가하면 여기에도 나옵니다(버튼이 한 줄에 5개로 바뀌어 여전히 두 줄). 기상 시각보다 이른 교시는 흐리게 표시되고, 누르면 고를 수 없는 이유를 알려 줍니다. |
| 잠자러 가기 | 자기 직전에 누르면 수면 기록이 시작됩니다. |
| 꼭 일어나야 하는 시각 | 다음 기상 시각. 아래에 어느 날 아침인지(예: “10/11(일) 내일 아침”) 표시됩니다. |

고른 교시와 기상 시각은 저장되어 다음에도 그대로입니다. 조건이나 기록이 바뀌면 이전 계산에 “바뀐 내용이 있어요 · 다시 계산해 주세요”가 표시됩니다. 계산 카드의 안내는 두 줄까지만 보이고(홈이 스크롤되지 않도록), 더 긴 안내는 계산 직후 아래 알림으로 전체가 한 번 보이며 **계산 근거** 탭에서도 볼 수 있습니다.

### 2.2.1 누른 버튼 표시

- 모든 버튼은 누르는 동안 살짝 작아지고, 누른 뒤 잠깐 빛납니다.
- 고르는 버튼(교시, 잠들기까지 걸린 시간, 밤잠/낮잠, 깬 직후 졸림)과 아래쪽 탭은 선택된 동안 색이 채워진 채로 유지됩니다.
- 지금 고를 수 없는 버튼(기상 시각보다 이른 교시, 아직 비교 결과가 없는 CSV 저장)은 빨갛게 빛나고 이유를 알려 줍니다.
- 설정·시간표를 바꾸고 아직 저장하지 않았으면 “바뀐 내용이 있어요” 안내와 함께 저장 버튼이 계속 빛납니다.
- 파일 저장, 새로 분석, 예시 끝내기, 졸림 기록처럼 화면 변화가 작은 동작은 끝나면 아래에 알림이 뜹니다. ‘지금 얼마나 졸린가요?’는 버튼 아래에 마지막 기록이 계속 보입니다.

### 2.3 잠자러 가기 → 일어났어요

1. 자기 직전에 **잠자러 가기**를 누릅니다. 어두운 수면 화면이 나오고, 기상 시각까지 몇 시간 잘 수 있는지와 연령별 최소 수면을 채우는지 알려 줍니다.
2. 화면을 끄고 잡니다(앱을 닫아도 기록은 이어집니다).
3. 일어나면 앱을 열고 **일어났어요**를 누릅니다. 앱을 켜 둔 채 잤다면, 1시간이 지난 뒤 잠금을 풀거나 화면을 누르는 순간 **일어나셨나요?** 창이 먼저 뜨고 그 시각이 일어난 시각으로 채워집니다.
4. 확인 창에서 고칠 수 있는 것
   - **잠든 시각**: 버튼을 누른 시각 + 잠들기까지 걸린 시간(바로·15분·30분·1시간 중 선택, 마지막 선택을 기억). 직접 고쳐도 됩니다.
   - **일어난 시각**, **밤잠(주수면)/낮잠**(3시간 이상이면 밤잠으로 자동 선택), **깬 직후 졸림**(선택, 1 매우 또렷 ~ 9 매우 졸림)
5. **기록 저장**을 누르면 끝입니다.

- 밤중에 잠깐 잠금을 풀었을 때 창이 뜨면 **아직 자는 중이에요**를 누릅니다(30분 동안 다시 묻지 않음). 대답 없이 화면을 끄면 창이 닫히고, 아침에 다시 열 때 그 시각으로 다시 묻습니다.
- 잘못 눌렀다면 수면 화면의 **잘못 눌렀어요(기록 취소)** 또는 확인 창의 **이번 측정 취소**를 누릅니다.
- 잠자러 간 지 16시간이 넘어서 열면, 일어난 **날짜**까지 고를 수 있게 바뀝니다.
- 낮잠도 같은 버튼으로 기록합니다.
- **알아둘 점**: 웹앱은 다른 앱을 쓰는 중이거나 앱이 닫혀 있을 때 휴대폰 잠금 해제를 알 수 없습니다. 그럴 때는 앱을 열고 **일어났어요**를 누르면 됩니다. 알람·푸시 알림 기능은 없습니다.

### 2.4 수면 기록 탭

- 기록이 최근 날짜부터 보입니다. **고치기**로 시각·종류·졸림을 바꾸거나 **이 기록 삭제**로 지웁니다.
- 버튼을 깜빡했다면 **＋ 직접 추가**를 누릅니다. 기록이 빠진 가장 최근 날짜가 자동으로 골라집니다. 일어난 날짜, 잠든·일어난 시각만 넣으면 됩니다.
- 하루에 밤잠은 하나만 둡니다. 밤중에 오래 깼다면 가장 긴 구간을 밤잠, 나머지를 낮잠으로 기록합니다.
- 다른 기록과 겹치거나 아직 오지 않은 시각은 저장되지 않고 이유가 표시됩니다.

### 2.5 취침 시각 계산

1. **내일 언제 집중할까요?**에서 교시를 고르고 **꼭 일어나야 하는 시각**을 확인합니다.
2. 홈 맨 위의 **최근 기록으로 취침 시각 계산하기**를 누릅니다.

- 연속 5일째부터 계산합니다(처음 4일은 모형 준비 기간, 10~14일 기록 권장). 빠진 날이 있으면 상태 칸이 그 날짜를 알려 줍니다.
- 잠들 수 있는 범위는 자동입니다: 지금(또는 연령별 탐색 상한만큼 일찍)부터 최소 수면시간보다 1시간 짧은 시각까지 15분 간격으로 비교합니다. 평소 수면이 더 길면 그 시각도 포함합니다.
- 결과 예: `22:30–23:00` · “늦어도 23:00 · 평소보다 30분 일찍”, `23:20` · “늦어도 23:30 · 평소처럼 자면 돼요”.
- 조건을 다 맞출 수 없을 때: “8시간을 채우기 어려워요”(지금 자도 부족), “오늘은 60분까지만 앞당겨요”(모형 조건을 위해 너무 많이 앞당겨야 할 때) 같은 안내가 나옵니다.

### 2.6 계산 근거 탭

최근 계산의 자세한 내용과 원리를 모아 둔 곳입니다.

- 권장 구간, 예상 수면시간, 세 조건(① 연령별 최소 수면 ② 고른 교시 내내 AL ≥ 0 ③ 필요 수면이 기상 전에 끝나는지, 참고), 평소처럼 잘 때와의 비교
- 24시간 그래프(수면압 S, 일주기 기준 C, 각성 지표 AL, 평소대로 잘 때 AL, 취침 마감, 고른 교시 음영)
- 모든 후보, 그래프 숫자 표(30분 간격), 가정을 바꿨을 때의 범위, **계산 결과 CSV 저장**
- 어떻게 계산하나요? / 어려운 말 풀이 / 분석 탭 계산 방법 / 한계와 주의

AL은 단위 없는 모형 값입니다. 확률·건강 점수·성적 예측이 아니며, 의료 판단이나 운전 등 안전 판단에 쓰지 않습니다.

### 2.7 분석 탭

탭을 열면 기록을 분석해 해설을 보여 줍니다(서버 연결 필요).

- 요약 칸: 최근 7일 평균 수면, 권장 시간 채운 날, 잠드는 시각의 흔들림(±분), 모형상 필요 수면을 채운 날
- **해설**: 수면시간 부족, 자고 일어나는 시각의 규칙성, 평일·주말 리듬 차이(사회적 시차), 필요 수면, 가장 최근 수면, 그 전 7일과 비교, 낮잠, 아침 졸림을 쉬운 말로 설명합니다. ‘±30분’, ‘1시간’ 같은 판단 기준은 앱의 표시 기준입니다.
- **최근 14일 수면** 막대 그래프(밤잠·최소 미만·낮잠)
- **지금 얼마나 졸린가요?**: 수업 중 비슷한 시각에 한 번씩 누르면 저장되고, 버튼 아래에 마지막 기록(시각·값·횟수)이 보입니다. 5일 이상 모이면 **탐구용: 모델 A·B·C 비교**에서 총수면시간(A), 평소 시각과의 일치(B), 수면압 + 일주기(C)와 졸림의 순위상관을 볼 수 있습니다(인과·정확도를 뜻하지 않음).
- **잠을 돕는 생활 습관**

### 2.8 설정 탭

- **나에 대해**: 연령대(만 나이, 기본 만 13–17세), 생활 유형, 시간대. 영유아·교대근무는 기록과 수면량 요약만 제공합니다.
- **학교 시간표**: 교시마다 시작·끝 시각. 기본값은 1교시 08:40–09:30, 2교시 09:40–10:30, 3교시 10:40–11:30, 4교시 12:30–13:20, 5교시 13:30–14:20, 6교시 14:30–15:20, 7교시 15:30–16:20, 방과후 16:30–18:00입니다.
  - 8교시가 있으면 **＋ 8교시 추가하기**를 누릅니다. 바로 앞 교시와 같은 길이·쉬는 시간으로 8교시(기본 16:30–17:20)가 방과후 앞에 생기고, 겹치는 방과후는 그 뒤(17:30–19:00)로 옮겨집니다. 9교시까지 추가할 수 있고, **− 8교시 빼기**로 마지막 교시를 뺍니다(7교시 아래로는 빠지지 않음).
  - 시각을 고치거나 교시를 추가·삭제·기본값으로 바꾼 내용은 **시간표 저장**을 눌러야 적용됩니다. 저장 전에는 바뀐 칸과 새 교시가 강조되고 “바뀐 내용이 있어요” 안내가 보이며, 다른 탭에 다녀와도(앱을 닫기 전까지) 그대로 남아 있습니다.
  - 빠진 교시를 골라 두었다면 저장할 때 선택에서도 빠집니다. **기본값으로**는 지금 교시 수를 유지한 채 기본 시각으로 되돌립니다.
  - v2.1의 기본 시간표를 그대로 쓰던 경우 새 기본값으로 자동으로 바뀝니다. 직접 고친 시간표는 그대로 둡니다.
- **기록 관리**: 백업 파일 저장, 백업 불러오기, 기록 CSV 저장, 이 기기의 기록 모두 지우기. 저장된 기록을 읽지 못하면 원본을 따로 보관하고 **읽지 못한 원본 저장** 버튼을 보여 줍니다.
- **둘러보기와 도움말**: 14일 예시(내 기록과 섞이지 않음, 위쪽 **예시 보는 중 · 끝내기**로 복귀), 사용법 다시 보기, 홈 화면 설치.

### 2.9 백업과 기기 옮기기

- 기록은 그 휴대폰의 그 브라우저에만 있습니다. 휴대폰을 바꾸거나 브라우저 데이터를 지우기 전에 **설정 → 백업 파일 저장**을 누릅니다.
- 새 기기에서 같은 주소를 열고 **백업 불러오기**로 옮깁니다(지금 기기의 기록을 바꾸므로 먼저 백업).
- 카카오톡 같은 앱 안에서 링크를 열면 그 앱 안의 브라우저에 따로 저장됩니다. 메뉴의 **다른 브라우저로 열기**로 Chrome·Safari에서 여는 것을 권합니다(앱이 안내 배너를 보여 줍니다).

## 3. 휴대폰에 앱처럼 설치하기 (PWA)

배포된 **HTTPS 주소**에서 설치합니다.

- **iPhone·iPad**: Safari에서 주소 열기 → 공유 → **홈 화면에 추가**.
- **Android**: Chrome에서 주소 열기 → 메뉴(⋮) → **앱 설치** 또는 **홈 화면에 추가**.
- 카카오톡 등 앱 안의 브라우저에서는 설치가 안 될 수 있으니 먼저 Chrome·Safari로 엽니다.

한 번 온라인으로 연 뒤에는 서버가 꺼져 있거나 오프라인이어도 앱이 바로 열리고, 수면 측정·기록·백업이 됩니다. 계산과 분석에만 서버 연결이 필요합니다.

## 4. 누구나 쓰도록 배포하기 (Render 무료 호스팅)

Python 서버가 필요하므로 GitHub Pages 같은 정적 호스팅만으로는 계산이 동작하지 않습니다. 아래는 이 패키지의 `render.yaml`로 Render에 배포하는 절차입니다. 데이터베이스·디스크·비밀키는 필요 없습니다.

### 4.1 GitHub 저장소 만들기

1. GitHub에서 **New repository**를 만듭니다(예: `rhythm-sleep`). 공개·비공개 모두 됩니다.
2. 저장소 첫 화면의 **uploading an existing file**을 눌러 `sleep_rhythm` 폴더 **안의 내용물 전체**를 끌어다 놓고 **Commit changes**를 누릅니다. 저장소 최상위에 `run.py`, `render.yaml`, `requirements.txt`, `sleepapp/`, `web/`이 보여야 합니다. 숨김 파일 `.python-version`(내용 `3.13`)은 빠져도 동작하지만(그때는 Render 기본 Python 사용), 버전을 고정하려면 **Add file → Create new file**로 만듭니다.
3. 개인 백업 JSON·CSV는 올리지 않습니다.

Git을 쓴다면:

```bash
cd sleep_rhythm
git init && git add . && git commit -m "Rhythm v2.2"
git branch -M main
git remote add origin https://github.com/<아이디>/rhythm-sleep.git
git push -u origin main
```

### 4.2 Render에 배포 (Blueprint, 권장)

1. https://render.com 에 가입하고 대시보드에서 **New → Blueprint**를 선택합니다.
2. GitHub 계정을 연결하고 4.1의 저장소를 고릅니다. Render가 `render.yaml`을 읽어 다음 서비스를 만듭니다.

   | 항목 | 값 |
   |---|---|
   | 종류 / 런타임 / 요금제 | Web Service / Python / Free |
   | 지역 | Singapore(한국과 가까운 지역) |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `python run.py --production --host 0.0.0.0 --no-browser` |
   | Health Check Path | `/healthz` |
   | 자동 재배포 | 커밋할 때마다 |

3. 적용하면 빌드가 시작됩니다. 서비스가 **Live**가 되면 `https://rhythm-sleep.onrender.com` 형태의 주소가 표시됩니다(이름이 이미 쓰이면 다른 주소).
4. 주소 뒤에 `/healthz`를 붙여 `{"status":"ok","version":"2.2.0"}`이 나오는지 확인합니다.

Blueprint를 쓰지 않으려면 **New → Web Service**에서 저장소를 고르고 Language를 Python, 위 표의 Build·Start Command와 Instance Type **Free**, Health Check Path `/healthz`를 같은 값으로 입력합니다. 앱은 Render가 주는 `PORT` 환경 변수를 자동으로 읽습니다.

### 4.3 이미 예전 버전을 배포했다면

GitHub 저장소의 파일을 새 내용물로 모두 바꿔 커밋하면(이번 버전에서 없앤 `docs/SOURCES.md`도 저장소에서 지웁니다) Render가 자동으로 다시 배포합니다. 기록(브라우저 저장)과 고른 교시는 그대로 이어집니다.

- v2.0을 쓰던 휴대폰: 인터넷에 연결된 상태로 다음에 열 때 바로 새 화면이 나옵니다(서버가 잠들어 있었다면 처음 열 때 1분쯤 걸릴 수 있음).
- v2.1을 쓰던 휴대폰: 처음 열 때는 저장된 v2.1 화면이 열리면서 새 버전을 받아 두고, **한 번 더 열 때** v2.2 화면으로 바뀝니다.
- 예전 화면이 계속 보이면 앱을 완전히 닫았다가 다시 엽니다.

### 4.4 배포 후 확인 순서

1. 휴대폰에서 주소 열기 → 시작 안내의 **닫기**와 **이 창 재접속까지 보지 않기** 확인. 버튼을 누를 때마다 빛나는지 확인.
2. **예시로 둘러보기** → 계산 → **계산 근거 ›** 그래프 → 분석 탭 해설 → 위쪽 **예시 보는 중 · 끝내기**.
3. **잠자러 가기** → 몇 분 뒤 **일어났어요** → 확인 창에서 시각 확인 → 저장 → 기록 탭에 보이는지.
4. 새로고침·앱 다시 열기 후 기록 유지 확인.
5. 백업 파일 저장 → 기록 지우기 → 백업 불러오기로 복원 확인.
6. 설정 → 학교 시간표 → **＋ 8교시 추가하기** → **시간표 저장** → 홈에 8교시 버튼이 생기고 화면이 스크롤되지 않는지 확인.
7. iPhone Safari·Android Chrome에서 홈 화면 설치 → 실행 확인. 비행기 모드에서도 앱이 열리는지 확인.

### 4.5 운영 메모

- **무료 인스턴스**: 15분 동안 요청이 없으면 잠들고, 다음 요청 때 다시 깨는 데 약 1분 걸립니다. 앱 화면은 휴대폰에 저장된 것으로 바로 열리고, 계산·분석 때만 “서버를 깨우는 중” 안내가 나옵니다(최대 75초 대기). 월 750시간 무료이며, Render는 무료 인스턴스를 운영 서비스용으로 권하지 않습니다.
- **업데이트**: GitHub에 수정본을 커밋하면 자동으로 다시 배포됩니다. 화면 파일이 바뀌면 앱 저장본도 자동으로 새로 받으므로 따로 버전을 바꿀 필요는 없습니다. 배포 전 `python -m unittest discover -s tests -v`와 `node --test tests/test_utils.mjs`를 실행합니다.
- **Python 버전**: `.python-version`에 `3.13`을 적어 두었습니다. Render 환경 변수 `PYTHON_VERSION`을 정하면 그것이 우선합니다.
- **사용자 지정 도메인**: Render 서비스 설정의 Custom Domains에서 연결하면 HTTPS 인증서가 자동 발급됩니다.
- **선택 보안 설정**: 환경 변수 `RHYTHM_ALLOWED_HOSTS`에 `rhythm-sleep.onrender.com`(여러 개면 쉼표로, 공백 없이)을 넣으면 다른 호스트 이름의 요청을 거절합니다. `/healthz`는 상태 확인을 위해 항상 응답합니다.
- **요청 제한**: 앱 자체에는 사용자별 요청 횟수 제한이 없고, 한 요청의 최대 크기는 512KB입니다.
- **개인정보**: 서버는 요청을 메모리에서 계산만 하고 저장하거나 요청 본문을 로그로 남기지 않습니다. 호스팅 업체는 접속 IP·시각 같은 접속 기록을 처리할 수 있습니다. 공개 운영 전 운영자 연락처와 개인정보 안내를 화면에 추가하는 것을 권합니다.

### 4.6 다른 방법

Docker가 있는 서버:

```bash
docker build -t rhythm-sleep .
docker run --rm -p 8000:8000 rhythm-sleep
```

Docker 없이 리눅스 서버에서(HTTPS 프록시 뒤에 둠):

```bash
python3 -m pip install -r requirements.txt
python3 run.py --production --host 0.0.0.0 --no-browser
```

`--production`은 Waitress 서버(4 스레드, 요청 본문 512KB 제한)로 실행합니다. 로컬 기본 서버(`python run.py`)는 개인 컴퓨터용이며 인터넷 공개용이 아닙니다.
