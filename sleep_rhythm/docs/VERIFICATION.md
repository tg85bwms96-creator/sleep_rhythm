## 4. 실행하지 못한 확인

- **실제 휴대폰**: iPhone·Android에서 화면 잠금·해제 때의 `visibilitychange`, 홈 화면 설치, 앱을 닫았다 열 때의 시작 안내, 서비스 워커 업데이트, 카카오톡 앱 내 브라우저, 누를 때 빛나는 정도와 손가락 터치 느낌, 시간표 칸의 실제 시간 선택기 표시와 글꼴 폭은 확인하지 못했다. 휴대폰 크기의 Chromium 에뮬레이션과 시뮬레이션으로만 확인했다. 배포 후 `START_HERE_KO.md`의 “배포 후 확인 순서”를 실제 기기로 먼저 실행한다.
- **4인치 화면(320×568)**: 홈이 약 40px 스크롤된다(v2.1과 같음). 한 화면 맞춤은 폭 360px 이상 휴대폰을 기준으로 측정했다.
- **Waitress 실제 구동, Docker 빌드, Render 실제 배포**: 이 개발 환경에서 패키지 저장소·Docker·계정을 쓸 수 없어 실행하지 않았다. 로컬 기본 서버로 모든 브라우저 테스트를 실행했다.
- **flake8·mypy**: 패키지 저장소에 접속할 수 없어 다시 실행하지 못했다(v2.0 때는 경고 0개). 대신 컴파일·문법 검사, 사용하지 않는 import·긴 줄 검사, pyright 타입 검사를 했다.
- **Windows에서의 실행기**: 포트 공유 방지, 방화벽 허용 창, 같은 Wi-Fi 휴대폰 접속은 Windows 기기와 실제 휴대폰이 없어 확인하지 못했다. 포트 공유 방지는 Python 표준 라이브러리 `socket.create_server()`가 Windows에서 쓰는 방식과 같다.
- **스크린리더 실제 사용, 다수 사용자 부하 시험, 외부 보안 감사**는 하지 않았다.
- **모형의 타당성**: 실제 사용자 기록으로 졸림 예측 성능이나 수면 개선 효과를 검증하지 않았다. 결과는 교육용 모형 계산이다.

자동 테스트 통과는 무오류나 건강관리 효과를 보장하지 않는다.
